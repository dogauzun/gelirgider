# Effort tracking

Tickets are not estimated. No story points, no sprints. Work flows through the
kanban board in project `GLG`. What we track is actual effort, per ticket, so
that ticket size can be compared afterwards.

Time, start to finish, per ticket. Ticket status drives it. `In Progress` when
work starts, `In Review` when the PR opens, `Done` when it merges. Jira keeps
the transition timestamps; no manual logging.

Ticket sizing rule stays: a ticket that looks like more than a day of work is a
planning smell. Split it before starting.
